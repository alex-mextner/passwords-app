# Development

How to set up a checkout, run every quality gate, and drive the GTK app inside a private
headless GNOME Shell. The gates are the ones listed in spec §12
(`docs/superpowers/specs/2026-10-10-passwords-app-design.md`).

## Setup

The app runs on the system Python, so the virtual environment reuses Ubuntu's PyGObject:

```sh
uv venv --python /usr/bin/python3 --system-site-packages .venv
uv pip install --python .venv/bin/python -e . --group dev
uv pip install --python .venv/bin/python --no-deps pygobject-stubs
```

Python tools (ruff, mypy, pyright, bandit, semgrep, pip-audit, reuse, codespell, vulture,
deptry, xenon, yamllint, pytest) come from the `dev` group. The remaining binaries are
installed per user, never with `sudo`:

| tool | install |
|---|---|
| shellcheck, shfmt, actionlint, zizmor, gitleaks | `brew install shellcheck shfmt actionlint zizmor gitleaks` |
| bun (browser extension gates) | `curl -fsSL https://bun.sh/install \| bash` |
| pre-commit | `uv tool install pre-commit && pre-commit install` |

These come from Ubuntu packages (already present on an Ubuntu 26.04 desktop):
`gnome-shell mutter dbus-daemon pipewire wireplumber gstreamer1.0-pipewire
gstreamer1.0-plugins-good gnome-keyring python3-gi gir1.2-gtk-4.0 gir1.2-adw-1
gir1.2-secret-1 desktop-file-utils appstream libglib2.0-bin libglib2.0-dev-bin
libxml2-utils ffmpeg`.

## Running the gates

```sh
scripts/check.sh              # everything (same as `all`)
scripts/check.sh lint types   # one or more groups
scripts/check.sh mypy ruff    # individual gates
scripts/check.sh --list       # every gate name
```

Every selected gate runs even after another one failed, its output goes to the terminal and
to `.check-logs/<gate>.log`, and a table at the end shows PASS, FAIL or SKIP per gate with the
tool's own count line. The exit status is non-zero when any gate failed. A gate whose input
does not exist yet is skipped (no `extension/`, no `.desktop` file, no tests with a marker);
a gate whose tool is missing fails and names the tool.

| group | gates | configured in |
|---|---|---|
| lint | ruff, ruff format, codespell, vulture, deptry, xenon (absolute B, module A, average A), reuse, yamllint, actionlint, zizmor, shellcheck, shfmt (`-i 2 -ci`) | `pyproject.toml` `[tool.*]`, `REUSE.toml`, `.yamllint.yaml` |
| types | mypy `--strict` (src + tests), pyright strict (src) | `pyproject.toml` |
| security | bandit, semgrep (`.semgrep/` project rules + registry `p/python`, `p/security-audit`, `p/secrets`), pip-audit (the resolved dependency closure, not the venv), gitleaks (git history) | `pyproject.toml`, `.semgrep/` |
| data | D-Bus XML (`gdbus-codegen`), desktop-file-validate, appstreamcli validate `--pedantic`, glib-compile-schemas `--strict` | — |
| extension | eslint `--max-warnings 0`, tsc `--noEmit`, prettier `--check`, web-ext lint `--warnings-as-errors`, bun audit, semgrep `p/typescript` | `extension/` |
| unit | pytest, every test without a layer marker | `pyproject.toml` |
| integration | pytest `-m integration` | |
| coverage | coverage ≥ 90% over `core`, `sync`, `store`, `keyring` (reuses the unit + integration data of the same run) | `scripts/check.sh` |
| gui / e2e / browser | pytest `-m gui` / `-m e2e` / `-m browser`, one worker | |
| bench | pytest `-m benchmark --benchmark-only` (budgets are asserted by the tests) | |

`CHECK_OFFLINE=1` limits semgrep to the project rules, for machines without network access.
`PYTEST_WORKERS` (default 2) sets xdist workers for unit and integration.

The extension gates call the binaries in `extension/node_modules/.bin`, so
`extension/package.json` must list `eslint`, `typescript`, `prettier` and `web-ext` as
devDependencies, and `bun run build` must produce `extension/dist/firefox`.

### Files generated by rig

`rig.yaml` (stack `backend/python`) installs the owner's standard CI gates: CodeQL,
dependency review, secret scan, leftover grep, PR checklist and review threads, plus their
helper scripts under `ci/`, and agent configuration under `.claude/`, `.codex/`, `.haft/` and
`.serena/`. Those files are rewritten by `rig apply`, so local edits would come back as drift.
`scripts/check.sh` therefore leaves them out of the shell, YAML and workflow gates; their
findings belong in the agent-tools repository. As generated on 2026-10-10 they have:
zizmor 18 findings (pull_request_target triggers in dependency-review, leftover-grep,
pr-checklist and review-threads; checkouts without `persist-credentials: false`; an unpinned
`actions/upload-artifact@v4` in codeql.yml; a `GITHUB_PATH` write in dependency-review.yml),
actionlint 1 (SC2155 in codeql.yml), yamllint 7 (line length), and shellcheck/shfmt findings in
`ci/*/*.sh`.

## Test isolation

`tests/conftest.py` runs before any test module is imported and points `HOME`,
`XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_CACHE_HOME`, `XDG_STATE_HOME` and `XDG_RUNTIME_DIR`
into a throwaway directory per pytest process, sets `DBUS_SESSION_BUS_ADDRESS` to a socket
that does not exist, and removes `DISPLAY`, `WAYLAND_DISPLAY`, `SSH_AUTH_SOCK` and the other
desktop-session variables. A test that forgets to use a harness therefore fails to connect
instead of reaching the real login keyring or `~/.config/passwords-app`. Tests that need a
bus use `private_bus` / `private_session` (`tests/harness/dbus_session.py`, a throwaway
gnome-keyring) or `GnomeShellSession`; both set their own addresses on top.
`tests/test_isolation.py` proves the net holds. Production code must resolve paths and bus
addresses at call time, never at import time, so this redirection reaches it.

## Pre-commit

`.pre-commit-config.yaml` runs the fast gates (gitleaks on staged changes, ruff, ruff
format, codespell, reuse, yamllint, actionlint, zizmor, shellcheck, shfmt, data files) by
calling `scripts/check.sh <gate>`, so each gate is configured in one place. Types, semgrep,
pip-audit and the test suites run in CI.

## CI

`.github/workflows/ci.yml` runs one job per group in an `ubuntu:26.04` container (pinned by
digest), with a shared setup action in `.github/actions/setup/` that installs the job's apt
packages and builds the venv exactly as above. Every action is pinned to a commit SHA,
permissions default to none, and checkouts do not persist credentials. `scorecard.yml` runs
OpenSSF Scorecard; `.github/dependabot.yml` updates pip, GitHub Actions and the extension's
npm dependencies weekly.

## Headless GNOME Shell for GUI tests

`tests/harness/gnome_shell.py` starts a private GNOME session for tests and proof
recordings:

```python
from tests.harness.gnome_shell import GnomeShellSession

with GnomeShellSession("1280x800", lang="ru_RU.UTF-8") as shell:
    shell.spawn([sys.executable, "-m", "passwords_app.app.main"])
    shell.wait_for_window("Passwords")
    shell.screenshot(Path("docs/proof/raw/main.png"))
    shell.start_recording(Path("docs/proof/raw/search.webm"))
    ...  # drive the app
    shell.stop_recording()
```

What it guarantees:

- **It never touches the real session.** Everything lives under a temporary root with its
  own `HOME` and XDG directories. The shell gets a private session bus and a private
  "system" bus, so it cannot register with the real logind or GDM. Child environments are
  built from an allowlist (only `TZ` and `TERM` come from the host), so no `DISPLAY`,
  `WAYLAND_DISPLAY`, bus address, agent socket or `LD_PRELOAD` leaks in. The private bus can
  activate only the screencast service; evolution, goa, gvfs and the portals cannot start.
- **Unsafe mode is limited to that session.** GNOME 50 has no `--unsafe-mode` flag. The
  harness writes a session mode and a three-line extension into its temporary root; the
  extension turns unsafe mode on, which opens `org.gnome.Shell.Eval`, `Screenshot` and
  `Introspect` to the test process. Neither file exists outside the root.
- **Deterministic frames.** Animations, notification banners, screen blanking and the welcome
  dialog are off; the shell starts on the desktop, not in the overview; the locale is
  `C.UTF-8` unless `lang` says otherwise.
- **Recordings are WebM.** `start_recording` forces a VP8/WebM pipeline (the shell would pick
  H.264/MP4 when openh264 is installed) and starts PipeWire and WirePlumber inside the
  session with audio, Bluetooth and camera monitors disabled. The screencast only produces a
  frame when something on screen changes.
- **Teardown leaves nothing behind.** Every child carries a per-session marker variable;
  `close()` stops the shell, the buses and PipeWire, then kills any process that still
  carries the marker (including services the bus activated), and removes the root.
- **One session at a time.** A per-user lock file serializes sessions across pytest workers
  and terminals.

`env()` returns the environment for launching any client inside the session, and
`eval_js()`, `windows()`, `wait_for_window()` and `wait_frames()` expose the shell for
assertions. Set `PASSWORDS_APP_KEEP_SHELL_ROOT=1` to keep the root and its `logs/` after a
failure.

Run the GUI layer with `nice -n 10 scripts/check.sh gui`.
